# theta0 单变量实验 —— ⚰️ 判死(2026-08-19)

**结论:官方 `theta0=5°` 就是对的,调大严重丢场景。这是"事后清算"家族的第六刀,也死了。**

## 问题与假设

`colmap_input.py:395` 源视图打分对每个共视 3D 点累加:

```python
view_score += exp(-(θ - theta0)² / (2·(θ≤theta0 ? σ1 : σ2)²))   # theta0=5, σ1=1, σ2=10
```

`5°` 是 MVSNet 那代为 **DTU 转台**调的(相机围成小罩、基线短)。b28 是手持环拍,
可用视差 **35.9°** ⇒ 代进公式得分 **0.0085**,只有 5° 配对的 **0.85%**。

假设:公式一直挑"挨着拍的邻居" → 视差不足 → 白墙深度沿视线滑动 → 墙面缺陷。

## 设计(单变量)

| | |
|---|---|
| 固定 | COLMAP **4.1.1** + DSP-SIFT(生产前端)· 权重 C(零DTU+BlendedMVS)· 同帧 · 同固定噪声 · 官方 `filter_depth` |
| 变量 | **只有 theta0**:5 / 10 / 15 / 25 |
| 参照 | 官方 `blendmvg` @θ₀=5 跑在同一重建上(用户判为"完全不翘")⇒ 同坐标系 |

重建(COLMAP 4.1.1,两条前端臂各 132/132 全注册):
DSP-SIFT 48,652 点 / 1.359px;原版 SIFT 35,406 点 / 1.353px
(DSP 多 37% 点、重投影几乎相同 —— 与参数家谱"DSP 用略大重投影换更多点"一致)

## 结果

| θ₀ | 点数(DSP臂) | 到参照 p99 | >2cm | >5cm |
|---|---|---|---|---|
| **5°(官方)** | 24,879,697 | 38.7mm | 3.82% | 0.63% |
| 10° | 23,926,003 (−3.8%) | 36.0mm | 3.35% | 0.53% |
| 15° | 21,048,155 (−15.4%) | 30.1mm | 2.55% | 0.32% |
| 25° | 14,173,583 (**−43.0%**) | 23.2mm | 1.39% | 0.25% |

指标全线单调变好 —— **但肉眼判死**:

> 用户原话:**"C @θ₀=15 和 C @θ₀=25 已经让场景严重缺失了,所以必须要用 θ₀=5(官方值)"**

⇒ 指标的"变好"是**幸存者效应**:融合留下的点少了自然更可信,代价是场景出洞。
用户第一优先级是**覆盖范围**,这笔交易不划算。**θ₀ 判死。**

## 🔴 更重要的:诊断本身被用户改判

我(和这条实验的前提)一直把缺陷描述成"**墙面翘起**"。用户看完四窗后改判:

> **"墙不是翘起一部分,而是正确的墙在正确的位置,同时出现了第二面墙跟旅行箱粘连"**

⇒ 不是形变,是**鬼层/重影**。这与平行会话的法医归因完全吻合
(`arch_decision_dense_first_2026-08-18/WALL_BATTLE.md`):

- 病灶 = **墙后致密偏移层**,中位缩进 ~4cm(沿视线 6cm),尾到 23cm
- **位姿被洗清**:三臂稠密同位置同形态,稀疏墙笔直(RMS 4.6mm)
- 源像素 = **空白白墙 + 旅行箱纯黑内衬**(全无纹理)← 正是"粘连"
- **conf 0.95–1.0 与真墙无差:网络自信地错**,`geo_mask≥3` 被"多视一致但错误"骗过

⇒ **theta0 是"视差/位姿"侧的杠杆,而真凶在深度网络对无纹理区的行为上。方向本身就错了。**
