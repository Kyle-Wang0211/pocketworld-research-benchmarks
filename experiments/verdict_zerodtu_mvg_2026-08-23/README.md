## 二、🏆 用户肉眼判决:**几乎追平官方 blendmvg**

> 用户原话:**"新权重的质量几乎已经跟官方 blendmvg 差不多了"**

2×2 因此填满:

| | 少数据(MVS) | 多数据(MVG) |

## 三、🔴 判据七连败 —— 今天最重要的发现

**所有七种几何判据都把 C 排在新权重之前,而用户肉眼说新权重几乎追平基准。**

| # | 判据 | 失败方式 |
|---|---|---|
| 1 | 点数 | 鬼墙点一个不少 |
| 2 | 覆盖(体素占据) | 鬼墙照样占体素,只是占错格子 |
| 3 | 局部粗糙度(k=15 PCA) | 量邻域厚度;平滑弯曲的墙与平墙读数一样 |
| 4 | 大平面残差拟合 | 自动定位不到目标墙(最大平面是地板 7.3×4.7m;次大平面族 75% 点偏离>2cm,不是干净平面) |
| 5 | 云对云 **arm→ref** | **惩罚合法的额外覆盖**(新权重比基准多 19% 点) |
| 6 | 云对云 **ref→arm** | 只罚缺失,抓不到"多出来的东西" |
| 7 | 鬼层质量(远点密度成团) | 被各臂自身点密度污染(dtu 点最少 ⇒ 显得最不致密 ⇒ 排第一,但它肉眼最差) |

### 门槛扫描(以为找到了病根,结果没有)

法医报告病灶是"缩进 ~4cm",而我最初的远点门槛是 5cm ⇒ 怀疑鬼墙整个落在门槛内被判成"贴基准"。
把门槛从 1cm 扫到 6cm:

| 门槛 | 排序 |
|---|---|
| >1cm / >2cm / >3cm / >4cm / >6cm | **全部是** `blend < C < 新权重 < dtu` |

**五个门槛排序完全一致,且全与肉眼相反。** 门槛不是原因。

### 结论

**"用户看到的东西"不在"点到最近点的距离"这个量里。**

两个候选解释(未验证):
1. **全云统计淹没局部缺陷** —— 一片几平方米的鬼墙在 3000 万点里可能只占千分之几
2. 用户判的是**结构语义**("这里不该有面墙"),不是数值距离

⇒ **我们没有、且今天造不出一把能自动判鬼墙的尺子。**
**所有实验的判决权在用户的眼睛,这一步不可省、不可自动化。**
任何"指标变好了"的报告在拿到肉眼确认前都不成立 —— 今天正反两个方向各栽过一次:
- 08-19:指标说 C 最好(点数/覆盖/粗糙度全第一),肉眼说 C 最差
- 08-23:指标说新权重比 C 差(七种判据一致),肉眼说新权重几乎追平最好的
