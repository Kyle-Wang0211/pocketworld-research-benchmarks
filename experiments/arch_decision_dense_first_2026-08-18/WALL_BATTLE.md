# 白墙偏移层战役(2026-08-18,决策书附录)

用户在全分辨率稠密页发现:白墙整面重建出来了,但**一部分像翅膀一样翘出去**。
本文档记录归因与四刀探针的全程。所有数字实测。

## 法医归因:深度网络,位姿被洗清

四朵云(P16k/P8k/GTO 稠密 + LightGlue 稀疏)同一定向包围盒对拍
(`_artifacts/lightglue_spike/wall_forensics_20260818/`,并排页 compare_wall.html):

- 病灶 = **墙后致密偏移层**:中位缩进 ~4cm(沿视线 6cm)、尾到 23cm,
  占墙面点 P16k 4.13% / P8k 8.34% / GTO 5.57% / 噪声臂 4.10%
- **三臂稠密(两个独立位姿引擎+噪声臂)同位置同形态,稀疏墙笔直**(0.65%、RMS 4.6mm、
  法向与稠密差 0.32°)⇒ 位姿被稀疏云直接洗清
- 偏移层源像素 = 空白白墙 + 旅行箱纯黑内衬,全是无纹理区
- **conf 0.95–1.0 与真墙无差** —— 网络自信地错;相邻视图共享同一偏差,
  geo_mask≥3 被"多视一致但错误"骗过(镜像鬼点同机制族)

预算只调节幅度不是根因(P8k 偏移层最大)。

## 四刀探针(判据全部事先钉死)

### 刀 A:DA3 跨源门 —— ⚰️ 死,死因比预设狠
预设失败模式是"4cm 被 2.5cm 本底淹没";实测是 **DA3-METRIC 在弱纹理斜视白墙上
交付不出 2.5cm**:锚点拟合后墙面残差 20–90cm,偏移层上 |DA3−墙| 中位 102cm =
比 MVS 病灶(6cm)**错 17 倍**;门在干净墙常开(τ=8cm 时 FPR 0.90)。
oracle 作弊拟合都要抬斜率 4.3–6.5 倍。08-07 的 2.5cm 是"可靠子集"(有纹理区)的数。
与 068fa6c(DA3 融合门在有纹理区零预测力)拼合 ⇒ **外部单目线两头全死**,
连带把"单目特征当重训供体"(MonoMVSNet/DepthSplat 式)在动训练前证伪。
产物:`_artifacts/da3_separation_probe_20260818/`。

### 刀 B:官方 conf 三通道门 —— ⚰️ 死,反向信号
conf0(全管线唯一真光度量,module.py:735-751)AUC **0.21**(pooled)/0.29(逐帧中位)——
偏移层比真墙**更自信**,信号是反的(错误深度恰是多视光度一致的)。
conf1/conf2(aleatoric 自估头,loss.py:58-65 从未受光度监督)pooled≈0.5,帧间不可迁移。
工作点:截 15.5% 偏移层要陪葬 60% 真墙 + **全图 55% 的点**。
任何官方置信度阈值门判死。产物:`_artifacts/wall_forensics_20260818/roc_conf_20260818.json`。

### 刀 C:锚点 Delaunay 平面先验 + 全局残差门 —— ⚰️ 死,但挖出真凶
ACMMP(MIT)几何骨架 + 我们的稀疏锚点(支撑点换源)。逐帧 AUC 中位 0.813(min 0.635),
"召回≥80% ∧ 误杀≤2%"在全部变体全部 τ 下**不存在**(80% 召回档误杀 27%)。
**oracle 对照(先验=真值平面,零构建误差)也只有 81%/2.8%** ⇒ 失败主因不是 Delaunay
(覆盖区先验与真值平面差 0.1–0.3cm),而是:

> 🔑 **真凶:干净墙面的 MVS 深度自身带 +1.6~2.5cm 系统性后偏,且逐帧漂移
> (fr107/125 整帧 +5cm)。** 6cm 病灶切不出一条 2–5cm 漂移的基线。

附带发现:重力垂直兜底门在此锚点密度下不可用(小三角法向被噪声支配,误杀 62–68%);
病灶小尾帧恰在锚点荒漠(与 MVS 同因失败),fr107 先验覆盖 0%。
产物:`_artifacts/delaunay_prior_20260818/`。

### 刀 D:逐帧校正探针(由刀 C 真凶直接催生)—— 进行中
思路:先用锚点把每帧低频偏差**校正掉**(移动点不删点,规避幸存者效应协议),
基线干净后 6cm 病灶才凸出来。判据(用户钉死):
① 校正后 clean 墙残差 p50 < 1cm;② oracle 工作点 81%/2.8% → **≥90%/≤2%**。

(锚点先验注入 + conf 头补光度监督,BlendedMVS 管线在手,1–2 周)。

## 采集几何诊断(真凶定位,用户假设检验)
墙被拍得很好:51 帧看到墙窗、存在 9.6°/13.1° 正对帧、全对视差 p50 35.9° ⇒ **采集侧无罪,
补拍引导治不了**。真凶 = **同走廊互证**:9 个雾贡献帧的 top-10 源全在同一采集走廊,
错误深度同簇凑够 geo_mask≥3(镜像鬼点机制);可用视差 35.9° 实选仅 8.7°;
正对帧被浪费两次(从未被选为源;自己当 ref 时源不看墙,融合墙点=0);
正对帧自身墙区深度崩 0.5m(无纹理盲区,选源救不回——两个探针均证实)。

## 两杠杆探针(判据事先钉死)
- **杠杆①选源改造(自研公式)**:9 雾帧换跨走廊源 → 雾 −94.9%(42,285→2,167),
  墙面 +7.9%(正向超出),全局守卫全绿。**机制证实**。但公式(官方分^0.1×可见性×多样性)
  是 agent 自研,被用户否决:"复刻!不要自研!!!!"(本战役第三次踩此铁律)。
- **杠杆②跨走廊融合门**:失败——全场 top-10 本来就同走廊小基线(p50 11°),
  墙和雾在源方向多样性上分布重叠,融合期切不开。反向坐实:救治只能在选源层。

## 官方选源配方全场景(复刻执行,结果=失败,附归因修正)
OpenMVS SelectNeighborViews+FilterNeighborViews 全套默认(fOptimAngle=12°/角门[3°,65°]/
尺度门[0.2,3.2]/16×16面积乘子;实现为公式的独立 Python 重写,零 AGPL 代码)全场景重选:
新选源平均角 p50 8.7°→14.5°,但**雾 4.50% 纹丝不动**,墙面还掉 9.6%。
⇒ **归因修正:OpenMVS 的 1.89% 干净墙,功劳在它的 PatchMatch 求解器与融合,不在选源公式**
(考古报告预警过"1.89% 是整链证据",押注选源是我的错误)。
⇒ 两家官方选源(MVSNet θ0=5°、OpenMVS 12° 公式)都治不了走廊病;
方向多样性只存在于 PatchMatch 求解器内部(COLMAP 逐像素/ACMMP),不可搬运。
