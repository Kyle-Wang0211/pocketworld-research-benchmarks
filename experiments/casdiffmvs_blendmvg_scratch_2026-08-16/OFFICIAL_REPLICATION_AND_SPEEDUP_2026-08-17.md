## 2. 基线的建立

### 2.1 真机 fixture(97 帧)

`tools/prep_phone_fixture.py`。素材 `phone_cap_20260811`:100 张 4032×3024 原图
(Lepton 解出的原始 JPEG)+ 97 条 refined COLMAP 位姿 + 49,253 稀疏点。

三个坑写在脚本头注释里:
1. **不要补 `diag(1,-1,-1)`** —— 投影实测判定(原样 98.6% 点在相机前 / 补翻转只剩 1.4%)
2. **frameId 不能按下标推**(0→tap-8, 1→tap-19, 2→tap-29,跳号无规律)
3. 可见性是投影近似,不考虑遮挡

### 2.2 🔴 分辨率必须 4:3(用户拍板)

我最初建成 896×512,把 4:3 原图**拉伸**进 16:9,竖直压 1.31×。
改成 **768×576**:精确 4:3、32 整除、**正是 BlendedMVS 原生训练分辨率**,
且 442,368 px 比 896×512 的 458,752 还少 3.6%(端上预算不涨反降)。

⚠️ **诚实记账:修完几乎没有可测收益。** `<1%` 46.53→46.60,`<5%` 79.93→80.33,
只有 p90 从 8.3→7.7 cm(−7%)有真实移动。**我此前把它列为质量杠杆是高估了。**
改还是要改(正确、免费、还快 3%),但别指望质量跃迁。

### 2.3 🔴 头号发现:推理不可复现

**同权重同输入跑两遍,99.98% 的像素不同,最大差 1.8 米。**

根因:`models/update.py:479` `img = (self.scale * torch.randn_like(inv_depth)).float()`
—— 扩散精化在推理时**随机起步**,是官方设计不是 bug。

| 同权重同输入两跑的相对深度差 | |
|---|---|
| p50 | 0.098% |
| p90 | 3.264% |
| **>1% 的像素** | **21.49%** |
| >5% 的像素 | 6.58% |

**但聚合指标稳到 ±0.04pp**(四种跑法 `<1%` 全在 46.53–46.60)—— 误差在 10 万观测上互相抵消。

⇒ **两层结论必须分开说:像素级不可复现,聚合指标可比。**
⇒ 任何逐比特对拍**必须先设种子**(`--seed`,逐帧 `manual_seed(seed+f)`),否则对拍的是噪声。

## 3. 提速:两把刀,合计 −16.8%

### 3.1 逐模块耗时(先量再动手)

单帧 226ms(nv5 口径),模型只有 **0.925 M 参数** —— 与参数量毫无关系。

| 模块 | ms | 归类 |
|---|---|---|
| depthnet(stage1 初始代价体,48 假设) | 64.8 | 🎯 代价体 |
| GetCost(嵌在 GRU 里,调 6 次) | 62.7 | 🎯 代价体 |
| GRU 本身 | 61.8 | 网络 |
| feature(5 视图特征金字塔) | 32.6 | 🎯 冗余 |
| context | 5.0 | 网络 |

⇒ 代价体相关 **54%**,网络本身只占 26%。

### 3.2 刀一:特征缓存(✅ 逐比特)

97 帧 × N 视图 = N×97 次特征计算,但只有 97 张不同的图 —— 每张被重算 N 遍。
eval 模式下 FeatureNet 是纯函数 ⇒ 缓存命中与重算**逐比特相同**。

官方配置下:**374.3 → 348.7 ms(−6.8%),4290 万像素零差异。**

### 3.3 刀二:3D→2D 卷积融合(数值等价 ~1e-6)

`models/conv3d_as_2d.py`(**副本存在 `tools/vendored_models_conv3d_as_2d.py`**,
vendored diffmvs 不入库)。Conv3d(k=3) ≡ 沿深度维移位堆进通道的**单次** Conv2d,权重重排不重训。

判据来自两个无关后端给出的同一个数:

| Conv3d(4→8,k3) on [1,4,48,72,96] | 原生 | 融合 | 提速 |
|---|---|---|---|
| PyTorch/MPS | 3.12 ms | 0.78 ms | **3.98×** |
| CoreML CPU+GPU | 14.72 ms | 3.71 ms | **3.97×** |
| ~~CoreML ALL(含 ANE)~~ | ~~2.00~~ | ~~2.20~~ | ~~0.91×~~ |

🔴 **ANE 出局 —— 用户拍板"不要 ANE,我需要跨端"**(一台代码走三端,给苹果开快路 = 把安卓/鸿蒙留在慢路)。
🔴 **勘误:我此前说"ANE 不支持 3D 卷积"是错的** —— 实测 ANE 上 Conv3d 最快,
记忆里 `.all` 整模型 1869ms 是**图划分/来回搬运**造成的。

**🔴 不是一刀全改** —— 11 个卷积逐层实测:

| 层 | 原生 | 融合 | 提速 | |
|---|---|---|---|---|
| pvw.0 / cr.conv0(4→8 s1) | 3.00 / 2.92 | 1.09 / 1.01 | 2.75× / 2.91× | ✅ |
| cr.conv1(8→8 s1) | 3.01 | 2.03 | 1.48× | ✅ |
| cr.conv3 / conv5 | 0.78 / 0.25 | 0.48 / 0.17 | 1.62× / 1.48× | ✅ |
| **cr.conv6 / conv7(转置)** | 1.71 / 6.57 | 0.36 / 1.07 | **4.75× / 6.16×** | ✅ 最大赢家 |
| pvw.1 / cr.prob(Cout=1) | 2.97 / 2.94 | 3.67 / 3.68 | **0.81× / 0.80×** | ⬜ 变慢 |
| cr.conv2 / conv4(stride=2) | 0.41 / 0.14 | 1.29 / 0.44 | **0.32×** | ⬜ 变慢 |

全 3D 24.69ms | 全 2D 15.28ms(1.62×)| **逐层取优 12.66ms(1.95×)**

**败因不是 FLOP,是物化了多少字节**:`Cout=1` 时卷积极便宜但仍要物化 3×Cin 的堆叠张量;
`stride=2` 时原生只产出 1/8 体积、本来就快。
⚰️ 也试过拆成 3 次 Conv2d 再相加 = **0.73×**(比原生还慢)⇒ 必须是**单次** conv 才赢。

**副产品比速度值钱**:CoreML **根本转不了** `ConvTranspose3d` 的 `output_padding`
(`EXPORT_MODE` + `_convT3d_export` 就是为绕它写的,注释还记着上一版绕错导致 p90 42% 边缘偏差)。
两个转置卷积都在"该融合"那一列 ⇒ **改完这一整类特判可整块删除。**

## 3.5 🏆 网络视图数 vs 融合邻居数:解耦后的帕累托前沿

**问题**:`num_view` 5→10 让推理从 226ms 涨到 374ms(+65%)。这笔钱花在哪儿了?

- 网络侧:代价体是 **O(num_view)** 的真算力
- 融合侧:几何一致性只是拿**已有深度图**做 numpy 重投影,多几个邻居**几乎不要钱**

`bench_fixture97.py --net-views N` 把两者解耦(网络只取前 N-1 个邻居,融合仍用全部 9 个)。

### 免费的那一半

| 网络 nv5,融合邻居数 | 最终存活 |
|---|---|
| 4 邻居 | 27.74% |
| **9 邻居** | **44.07%(+59%)** |

**零算力代价。这一条无论网络跑几个视图都该开。**

### 完整前沿(融合固定 9 邻居)

| 配置 | ms/帧 | `<1%` | 误差中位 | 零认同 | 融合存活 |
|---|---|---|---|---|---|
| 网络nv5 + 两刀 | **191.4** | 46.75% | 0.89 cm | 28.55% | 44.07% |
| 网络nv7 + 两刀 | **239.7** | 48.75% | 0.82 cm | 25.91% | 48.77% |
| 网络nv5(无刀) | 241.3 | 46.75% | 0.89 cm | 28.55% | 44.07% |
| **网络nv10 + 两刀** | **311.6** | **49.75%** | **0.80 cm** | 23.80% | 51.73% |
| 网络nv7(无刀) | 306.6 | 48.75% | 0.82 cm | — | 48.77% |
| 官方 nv10(无刀) | 374.3 | 49.75% | 0.80 cm | 23.80% | 51.73% |

### 🔑 结论:降 `num_view` 换速度是劣势策略,被无损刀完全支配

- `nv7+两刀 239.7ms` vs `nv5无刀 241.3ms` —— **同速,前者 `<1%` 高 2pp、误差低 0.07cm**
- `nv10+两刀 311.6ms` vs `nv7无刀 306.6ms` —— **同速,前者又更好**

**在每一个速度点上,"官方 num_view + 无损刀"都优于"降 num_view + 无刀"。**
⇒ 不该动 `num_view`,该把刀磨快。出货配置 = **311.6ms,官方质量零损失**;
若需降级档,239.7ms(nv7)代价是 `<1%` 掉 1pp、误差中位 +0.02cm。

⚠️ 网络视图数买到的是**真精度**不只是存活率(误差中位 0.89→0.80cm),所以
不能拿"存活率差不多"当理由砍 `num_view`。

## 5. 诊断工具与方法学

### 5.1 几何一致性 —— 唯一对无纹理区有效的判据

`tools/diagnose_depth.py`。参考帧像素 → 投源视图 → 取源视图深度 → 反投 → 投回参考帧,
要求重投影 <1px 且相对深度差 <1%。**这个判据对白墙/地板同样有效**,
不像稀疏点指标那样是瞎的(SfM 点只长在有纹理处 —— 08-17 已被肉眼推翻过一次)。

### 5.2 稀疏点指标的三个已知失真(报但不修)

1. 可见性是投影近似 ⇒ 遮挡点贡献假误差。**NEAR3**(每点只算最近 3 台相机,
   track_len 实测 2.878,量级对得上)把 p90 从 **71.6cm 拉到 8.3cm** —— 遮挡污染被这一刀坐实
2. SfM 点只长在有纹理处 ⇒ 对无纹理区结构性失明
3. 稀疏点自身有 1.2213 px 重投影误差,是"另一个估计"不是真值

⚠️ **`<1%` 是相对阈值**:本素材中位深度 0.8m ⇒ 1% = **8mm**。
不能与 sub138 的 78.6% 直接比 —— 那是 5m 场景,1% = 5cm。
⚠️ 绝对值随帧子集浮动(30 帧 26.47% vs 40 帧 33.07%),**臂间对照有效,不可跨表引用**。

### 5.3 模糊是结构性的

级联的实际分工:`stage1(1/8) → 上采样 → stage2(1/4) → 上采样 → stage3(1/2) → 上采样 → 全分辨率`。
**最后一级没有代价体、没有 GRU,纯学习式插值。**

证据(降到 1/2 再升回来,与原图 >1% 的像素):

| | |
|---|---|
| 降到 1/2 再还原 | **3.06%** |
| 降到 1/4 再还原 | 7.45% |
| (参照)模型自身扩散噪声 | 21.5% |

**信息损失比模型自己的随机噪声还小** ⇒ 全分辨率那一层几乎不带新信息。

分辨率对锐度的作用(07-31 报告 §四"未做"里点名的空白,本次补上):

| 判据 | LO 768×576 | HI 1408×1056 |
|---|---|---|
| 统一降到 768×576 再往返 | 3.06% | **4.38%** ✅ +43% 细节 |
| **边缘锐度比(边缘/非边缘深度梯度)** | 1.64× | **1.61×** ❌ 无改善 |
| 零视图认同 | 26.47% | **38.33%** 🔴 变差 |
| 代价 | 226ms / 472MB | 691ms / 1381MB |

⇒ **分辨率买到纹理级细节密度,买不到物体边界的锐利。** 07-31 的"离开参数空间"结论在锐度这根轴上依然成立。

### 5.4 端上内存墙(引 07-31 实测拟合)

峰值 ≈ **87MB + 870MB/Mpx**(896×512 预测 486 / 实测 485;1600×1152 预测 1691 / 实测 1683)。
1.5GB 反解上限 = **1.624 Mpx** ⇒ 4:3 且 32 整除的最大档 = **1408×1056(1381MB)**。

## 6. "老素材好、新素材差"——前提被推翻

|---|---|---|
| 老素材 413 帧 · 5–10m 大空间 | **36.24%** | 47.05% |
| 新素材 97 帧 · 0.9m 近距离 | **33.07%** | 47.88% |

**新素材不但没变差,还略好** —— 且是在严 5.5 倍的绝对容差下(1% 在 5m = 5cm,在 0.9m = **9mm**)。

(geo3+法向+边缘 + voxel 5mm + 统计离群清理)。而我给出的是 `conf≥0.5`,**存活 87.9%**。
