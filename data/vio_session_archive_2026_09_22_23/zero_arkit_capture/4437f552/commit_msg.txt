开关 ON 时按下快门,成片从来进不了库。静态排查到三处断点(integration@3e50521),
写代码时又发现第四处:

① 逐帧持久化闸 `arMetadataReady` 要 `scaleAlignAnchorCount >= 8`。VIO 臂如实报 0
  (出货引擎 `XRSLAMGetResult(RESULT_FEATURES)` 空实现,09-19 实证,不许编数)
  ⇒ 每帧 `skip persist: … anchors=0`。
  → 新增 `_poseSourceRequiresScaleAlignAnchors(source)`,穷举 switch 照抄 A 的
    `_poseSourceCarriesCameraGeometry` 形状:arkit true(不变)/ xrslam false /
    imu false / 未知 throw。逐帧闸对 arkit 的布尔式逐位同旧式。
② `VioArPoseProvider.captureHighResolutionStill` 拍一张返回 null;session 接着调
  `saveCurrentFrame`,VIO 又拍一张并报 `saved_elsewhere`(原生自己选路径)
  ⇒ `photo not promoted`,而且一次快门两次曝光。
  → `captureHighResolutionStill` 返回 null **且不拍**,活让给 `saveCurrentFrame`;
    `saveCurrentFrame(spec)` 只拍一张,JPEG `File.rename` 到 `spec.jpegPath`
    (跨卷退 copy+delete),`spec.metadataPath` 写 sidecar,两个文件都落地才报
    `saved`,任何一步失败如实非 saved + message(no_pose / unsupported /
    native_format_not_jpeg / jpeg_missing / jpeg_move_failed / metadata_write_failed)。
    `requestPhoto` 串行成一条 Future 链:原生只有一个结果槽,并发两条会让先完成的
    那张被覆盖、轮询方按 requestId 等到超时。
③ `_isCompleteArFrameSidecar` 要 `anchors_world` 非空 + `anchor_depth_count >= 8`。
  → 读 sidecar 的 `poseSource` 键(与 `_sampleToCanonicalJson` 同名),缺键按
    arkit(旧 sidecar 语义不变),再走 ① 的同一个 switch。
    `_fallbackStillFromMetadata` 的 captureKind 按源分:arkit 仍是
    `arkit_frame_fallback_jpeg` / `nearest_ar_frame_snapshot` 一个字符不改,
    xrslam 另起 `xrslam_frame_fallback_jpeg` / `vio_pose_at_trigger`。
④(排查没列到)生产采集页只以 `manualCapture: true` 起会话(`_startManualCapture`
  两个入口都是),快门走 `captureSinglePhoto` → `_captureOfficialHighResInput`,
  那条路上 null still 是终态 `captureFailed`,**没有** `_onPoseTick` 那种 fallback
  ⇒ 只改 ①②③ 依然一张进不了库。
  → 新增 `_poseSourcePromotesStillViaFrameSidecar(source)`(arkit false 不变 /
    xrslam true / imu false / 未知 throw)与 `_promoteStillViaFrameSidecar`:
    null still 时 `saveCurrentFrame(evidenceSpec)` → `_hasCompleteArFrameSidecar`
    → `_fallbackStillFromMetadata`,再进既有 validate/commit。4032×3024 硬闸不放宽。
