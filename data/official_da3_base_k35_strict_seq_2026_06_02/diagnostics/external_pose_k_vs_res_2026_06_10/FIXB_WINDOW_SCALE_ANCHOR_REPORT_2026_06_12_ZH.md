# 修法 B（稀疏锚·观测关联版）定案报告 — DA3 窗间尺度对齐 production 配方

2026-06-12 深夜，用户拍板：**修法 B（观测关联版）定为 production 配方进管线。**
模块：`tools/python/da3_window_scale_fixb.py`（含 `--self-test` 金标自检）。

## 1. 问题

pose-conditioned DA3 的 K18 窗共享同一套 ARKit 位姿系，但每窗深度是"网络单位"，
官方 umeyama 回标定每窗有独立误差 → 融合时同一表面双层皮（柜子/地板重影）。
实测（45 窗全量 sweep）：高信窗残差 3-6%，最差窗 **28.5%**。

## 2. 验证链（当天完成，全部真实素材）

| 实验 | 内容 | 关键数字 |
|---|---|---|
| expD | 暗光手机场 3 窗 | 残差 26-29% 且比值不互逆 → 暗光是采集闸门问题，对齐救不了 |
| expD2 | 好光照 414 集 3 窗，修法 A（重叠链式标量） | 高信对 3.3cm → **5.5mm@1m**（conf75） |
| expE | 修法 B（局部稀疏锚独立标量）+ v1 三角化器原型 | 1564 锚 8 秒 CPU；B 比值独立复现 A 至 0.1-0.4%；目检红绿蓝融合 ✓ |
| expF2 | 全 45 窗 + 全场 29k 锚（几何投影关联） | **遮挡 bug**：被前景挡住的锚砸在前景像素上，中位比值单边拖大（max 1.285）→ 交付云"竖条撕裂"，用户目检抓出 |
| expF3 | 观测关联版（锚只对真正匹配过它的帧投票） | 金标恢复：win25 差 1.13%、win26 差 0.79%；easy 窗标量回到 ±1.5%（win41 真实 6%）|

## 3. Production 配方（锁定）

1. **锚点**：用拍摄自身帧 + 已知 pose 三角化（SIFT@1536、span-6 极线门 3px、
   union-find tracks、多视 DLT、cheirality + 重投影 ≤2.5px + 视差 ≥1.5°）。
   414 帧 → 29k 锚 / 143k 观测，CPU ~84s（冷）/ 4s（特征缓存后）。
2. **每窗 1 标量，观测关联**：锚只通过"真正观测过它的帧"投票（可见性来自特征匹配
   关系，**禁止全场锚几何投影**——expF2 的撕裂就是这么来的），在观测像素处对深度；
   两级鲁棒拟合 |log r|≤log1.15 → 中位 ±log1.05；MIN_OBS=300。
3. **授权语义**：锚定标量只授权给 conf_median ≥ 6.0 的窗（自检中 11/45 个授权窗
   与原版 easy-11 完全重合）；低信窗误差是**区域性的、不存在单一真标量**
   （win28：锚定 0.928 vs 大面 0.974，两者都"对"），继承最近授权窗的标量保持
   全局系一致，真正的治疗是融合期 conf 门控。
4. 配套既有结论：官方 umeyama 保留（修法 B 是其上的残差修正）；conf75 融合门控。

## 7. 教训（写进流程）

- **数字大发现先怀疑仪器**：s_B=1.2852 本应立刻触发遮挡排查，而不是当"大发现"。
- **目检是验收的一部分**：撕裂是用户肉眼抓的，残差中位数没报警（它只量重叠区一致性，
  量不出"整窗被推走"）。后续凡交付点云必附 pre/post 切换目检。
- 边缘滤波（3×3 邻域一致性）在本数据上是无效操作——低信窗偏差不是轮廓采样问题。
